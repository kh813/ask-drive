# AskDrive (`ask_drive`)

**Google Drive ドキュメント ナレッジ回答ボット**

Apple Silicon Mac (8GB〜) の単一マシン上で、Google Drive 内の共有マニュアル・規定ドキュメントを取り込み、夜間バッチで事前生成した想定 QA・要約・構造化データを用いて、営業時間中の問い合わせに **1秒未満で即答（または原文抜粋を提示）** するシステムです。

推論基盤は **完全ローカル（Ollama / LM Studio）** と **外部 API（Gemini / Claude / OpenAI）** から選択できます。既定は完全ローカルで、外部 API は管理者が明示的に有効化した場合にのみ使われます。

---

## 主な特徴

1. **LLM プロバイダを選択可能**:
   - **Ollama**（既定・完全ローカル）: 埋め込み `bge-m3` / 夜間生成 `qwen3:4b`
   - **LM Studio**（ローカル・OpenAI 互換）
   - **Google Gemini API** / **Anthropic Claude API** / **OpenAI API**
   - **生成用と埋め込み用を個別に設定できます。** 「埋め込みはローカルのまま、生成だけ Claude」といった構成が可能です。
   - 既定構成では外部 LLM API への社内データ送信は一切行いません。外部 API を選んだ場合のみ、文書本文がそのプロバイダに送信されます（画面に常時表示されます）。
2. **二相運用 (Phase-based Residency Control)**（ローカルプロバイダ利用時）:
   - **営業時間相 (07:00〜19:00)**: 埋め込みモデルのみ常駐、LLM 生成 API 封鎖（メモリ圧迫防止）。
   - **待機相 (19:00〜02:00)**: 全モデル解放。
   - **夜間バッチ相 (02:00〜06:30)**: フェーズごとに1モデルのみロードし、RAM ピークを最小化。
   - 外部 API を生成に使う場合はローカル RAM を消費しないため、この制約は自動的に解除されます。
3. **段階的応答 (Multi-tier Answering)**:
   - **Tier 0**: 正規化完全一致キャッシュ（数ミリ秒）
   - **Tier 1**: 想定 QA ベクトル検索（1秒未満・類似度 >= 0.90）
   - **Tier 2**: 原文ハイブリッド検索（`sqlite-vec` + FTS5 trigram + RRF 融合）による原文抜粋提示
   - **Tier 3**: 未回答質問の自動ロギングと翌夜バッチでの最優先回答生成
4. **Google ログインとドメイン制限**:
   - 利用には Google アカウントでのログインが必須です。
   - 事前に設定した自社ドメイン（`@company.com`）のアカウントのみアクセスを許可し、部外者のアクセスを遮断。
5. **Drive 同期はサービスアカウントにも対応**:
   - ブラウザでの認可が不要な**サービスアカウント方式**を選べます（推奨）。Google が OAuth の `redirect_uri` に課す制約（LAN の生の IP アドレスや `.local` ホスト名の拒否）を受けず、社内 DNS の整備なしに LAN のどこからでも Drive 同期を動かせます。
   - 社内限定の共有ドライブも、**ドメイン全体の委任**（サービスアカウントが社内の同期専用ユーザーとして読み取る）で同期できます。
   - 個人アカウントでの OAuth 連携（従来方式）も引き続き選べます。
6. **sudo 方式の管理者権限昇格**:
   - 全員が**一般ユーザー**としてログインします。常時の管理者アカウントは存在しません。
   - 許可されたアカウント（全体管理者）だけが、**各自のアカウントで本人確認**をして、そのセッションの間だけ全体管理に入れます（Secure LDAP なら本人のパスワード、それ以外は 10 分以内のログイン）。共有の管理者パスワードはありません。
   - 昇格の成功・失敗・解除はすべて**監査ログ**に記録され、誰のアカウントから昇格したか後から確認できます。
   - 一定時間（既定 30 分）で自動的に降格します。
7. **Web 管理画面 (`/admin`、昇格中のみ)**:
   - バッチ状況、ナレッジカバレッジ、未回答質問、文書一覧、Drive フォルダ設定、LLM プロバイダ設定、ユーザー管理、昇格履歴、メンテナンスモード切り替え。

## 必要環境

- **OS**:
  - macOS (Apple Silicon / Intel, Apple Silicon 推奨)
  - **Linux (x64 / arm64)**: Ubuntu 22.04 / 24.04、Debian 12 以降（systemd 必須）
- **管理者権限 (sudo)**:
  - macOS: **不要**（`./app.sh setup` がスタンドアロンバイナリおよびローカル環境 `.runtime` に必要なツール群を自動ダウンロード・セットアップします）
  - Linux: **初回のみ必要**（`./app.sh setup` の apt パッケージ導入と `./app.sh service install` の systemd 登録）。以後の起動・停止・再起動・`./app.sh deploy` は sudo のパスワードなしで動きます（下記「Linux（systemd）」）

## インストールと初期セットアップ

### 1. リリースアーカイブ（ZIP）の取得と展開
GitHub Releases から最新版の ZIP をダウンロードして展開します。
```bash
# 例: v0.0.19 の場合
curl -fLO https://github.com/kh813/ask-drive/releases/download/v0.0.19/ask-drive-v0.0.19.zip
unzip ask-drive-v0.0.19.zip -d ask-drive
cd ask-drive
```

### 2. 初期セットアップの実行
統合管理スクリプト `./app.sh setup` を実行します。
```bash
./app.sh setup
```
> **API キーはあとで登録できます**: Gemini などの外部 API を使う予定で、まだ API キーが発行されていない場合は、キーの入力を空欄のまま Enter で進めてください。キーが発行されたら、窓口の管理画面の「設定」タブで登録します。登録するまで、夜間バッチ（文書の取り込み・QA 生成）は実行されず、管理画面にその旨が表示されます。生成・埋め込みとも外部 API を選んだ場合、Ollama（ローカル推論）はインストールせず、`./app.sh start` でも起動しません（あとで使う場合は `./app.sh repair-ollama` でインストールし、管理画面で Ollama に切り替えると、アプリが Ollama を起動します）。起動時のヘルスチェックには「[!] API キーが未設定です」と表示されます。

> **自動実行される処理（管理者権限不要）:**
> 1. **依存ツールの確認 & 自動配置**: `pandoc`, `ollama`, `poppler` (pdftotext), `erlang`, `elixir`, `sqlite-vec` を検出し、未インストールの場合はローカル環境（`.runtime/`）へ自動取得・セットアップ
> 2. **初期設定の対話入力**: LLM プロバイダ、モデル、API キーを尋ねます（後から管理画面で変更できます）。**Google Workspace ドメインと全体管理者はここでは聞かず、初回に Web 画面へアクセスしたときに設定します**（下記「3. 初回セットアップ（Web）」）
> 3. **Ollama モデルの自動取得**: ローカルプロバイダを選んだ場合のみ、`bge-m3` / `qwen3:4b` を自動ダウンロード
> 4. **環境設定ファイル生成**: `.env.prod` の自動生成と暗号化キー生成
> 5. **データベース構築 & リリースビルド**: SQLite DB の作成、マイグレーション、プロダクションアセットとリリースの完全ビルド

### 3. 初回セットアップ（Web）

セットアップ後、ブラウザで `https://<ホスト>:4443/` を開くと **初回セットアップ画面** が表示されます（完了するまで、どのページを開いてもこの画面になります）。

1. **セットアップコード**: サーバーを操作できる人だけが最初の管理者になれるよう、サーバー上で確認できるコードを入力します。コードは `./app.sh status` の表示、またはサーバーの起動ログ（「セットアップコード: XXXX-XXXX-XXXX」）で確認できます。10 回続けて間違えると 15 分間受け付けません。
2. **組織の Google Workspace ドメイン**（例: `company.com`）: Google ログイン（SSO）と Google Drive の連携で、このドメインのアカウントだけを受け付けます。
3. **最初の窓口の名前**（既定 IT-Support。あとから変更可）
4. **全体管理者のメールアドレス**（複数可）: AskDrive 全体を管理する人で、最初の窓口（IT-Support）の担当者にもなります。全体管理には各自のアカウントで本人確認して入ります（共有のパスワードはありません）

完了するとコードは無効になり、全体管理の「窓口（アプリ）」画面に移ります。次に窓口の管理画面で Google Drive と AI を設定してください。最初の窓口は **夜間の自動実行がオフ（設定中）** で始まります。「今すぐ実行」「取り込みのみ」で手動でテストし、準備ができたら窓口の「概要」の **「自動実行をオンにする」** を押してください（新しく作る窓口も同じです。窓口の「設定」の「夜間の自動実行」でも切り替えられます）。ドメインと Google ログインの OAuth 資格情報は、あとから全体管理の「全体設定」→「組織（Google Workspace）」で変更できます。

> 全体管理者とドメインが設定済みの既存環境では、初回セットアップ画面は表示されません。

対話入力の例:

```text
[LLM プロバイダの選択]
  1) ollama    - ローカル推論（既定・完全ローカル、追加費用なし）
  2) lmstudio  - LM Studio のローカルサーバー（OpenAI 互換）
  3) gemini    - Google Gemini API
  4) anthropic - Anthropic Claude API
  5) openai    - OpenAI API

回答生成に使うプロバイダ [1-5] (既定: 1): 4
生成モデル名 (既定: claude-sonnet-5):
Anthropic API キー: ********

埋め込みに使うプロバイダ [1,2,3,5] (既定: 1): 1
埋め込みモデル名 (既定: bge-m3):
埋め込み次元 (既定: 1024):

```

> **注意**: 外部 API プロバイダを選ぶと、文書本文と質問がそのプロバイダに送信されます。機密文書を扱う場合は `ollama` または `lmstudio` を選んでください。


### 3. アプリケーションの起動

#### フォアグラウンド起動（開発・テスト用）:
```bash
./app.sh start
```

#### 常駐サービス登録・起動（推奨。macOS: launchd / Linux: systemd）:
```bash
./app.sh service install
./app.sh service start
```
サービス状態の確認:
```bash
./app.sh service status
```

#### Linux（systemd）

- `./app.sh setup` は最初に `sudo apt-get install` で `poppler-utils`（pdftotext）・`zstd`・`unzip`・`git`・`curl`・`openssl`・`build-essential` を入れ、Erlang/OTP 28・Elixir 1.19・pandoc・Ollama・sqlite-vec（`vec0.so`）は `.runtime/` と `priv/sqlite_vec/` に配置します（Homebrew は使いません）。
- `./app.sh service install` は **systemd のシステムサービス** `/etc/systemd/system/askdrive.service` を作成し、`enable --now` で起動します。サービスは `service install` を実行したユーザーの権限で動き（root では動きません）、ログは `log/ask_drive.log` / `log/ask_drive_error.log` に追記されます。
- 同時に `/etc/sudoers.d/askdrive` を作成し、そのユーザーに **`systemctl start|stop|restart askdrive.service` だけ**をパスワードなしで許可します。これにより、管理画面からの証明書の適用（再起動）や `./app.sh deploy` の再起動が sudo のパスワードなしで動きます。
- 状態・ログ: `./app.sh status`、`systemctl status askdrive`、`journalctl -u askdrive`
- 解除: `./app.sh service uninstall`（sudo が必要）

ブラウザで `https://localhost:4443/` にアクセスします（`http://localhost:4000/` も HTTPS に転送されます。初回は自己署名証明書の警告が出ます。詳しくは「HTTPS（SSL）」を参照）。

| `./app.sh service start` | 常駐サービスを開始 |
| `./app.sh service stop` | 常駐サービスを停止 |
| `./app.sh service restart` | 常駐サービスを再起動 |
| `./app.sh service status` | 常駐サービスの稼働状態およびログ確認 |

### 管理者のロックアウトからの復旧

全体管理者が無くなった場合は CLI から復旧できます。LDAP が使えず本人確認ができない場合は、下の「締め出されたとき」の `./app.sh auth ldap off` で LDAP を止めると、10 分以内のログイン（Google ログイン）で入れるようになります。

```bash
# 指定アカウントを全体管理者にする
./app.sh admin grant you@company.com
```

### Web 管理画面を使わずに Drive 同期を設定する

Drive 同期の設定は本来 Web 管理画面（ログイン + 管理者昇格が必要）から行いますが、社員ログインの OAuth がまだ通っていない、あるいは LDAP が使えないなどの理由でそこに到達できない場合は、**サービスアカウント方式**（後述の「ステップ3・方式A」参照）を CLI から直接設定できます。Web 側の認証状態に一切依存しません。

JSON ファイルが手元にある場合、パスを直接指定できます:

```bash
./app.sh drive service-account /path/to/service-account-key.json
```

**AskDrive のインストールディレクトリ（`ask-drive/` 直下）に決まった名前で置いておけば、パスを省略しても自動で読み込まれます。** 次のいずれかの名前を使ってください:

- `credential.json`
- `credentials.json`
- `service-account.json`
- `service-account-key.json`

```bash
# ask-drive/credential.json を配置済みなら、パス指定なしでそのまま検出されます
./app.sh drive service-account
```

該当するファイルが1つも無い場合は、Google Cloud Console からダウンロードした JSON の中身をその場に貼り付けて設定できます（貼り付け後、空行または Ctrl+D で確定）。複数の候補ファイルが同時に存在する場合は、誤って別プロジェクトのフォルダに同期してしまう事故を避けるため自動選択せず、パスを明示するよう案内されます。

> サービスアカウントの秘密鍵は Google が発行するものなので、値を1つずつ質問して新規に作ることはできません。ここでの「対話的」入力は、Google からダウンロードした JSON の**貼り付け**を指します。

JSON の妥当性（`client_email` / `private_key` の有無）をその場で検証し、暗号化して保存します。実行後は表示されたサービスアカウントのメールアドレスを、同期対象の Google Drive フォルダに閲覧者として共有してください。

同期対象が **社内限定の共有ドライブ** にあってサービスアカウントを共有に追加できない場合は、`--subject` でドメイン全体の委任を使います（詳細は「ステップ3・方式A」の「社内限定の共有ドライブを同期する場合」）:

```bash
# キーの登録と同時に設定
./app.sh drive service-account /path/to/key.json --subject sync@example.com
# 登録済みのキーはそのままで、アクセスユーザーだけ設定・変更
./app.sh drive service-account --subject sync@example.com
# 委任をやめてサービスアカウント自身でアクセスする
./app.sh drive service-account --subject ""
```

## 複数の窓口（マルチアプリ）と管理者権限

v0.0.47 以降、1 つの AskDrive の中で、部門ごとの相談窓口を並列に動かせます（例: 情報システム部の「IT-Support」、人事部の「HR」）。窓口ごとに Google Drive のフォルダ、Gemini / Claude / OpenAI などの API キー（費用を窓口ごとに分けられます）、検索インデックス、QA、質問ログ、夜間バッチの履歴が分かれ、データは窓口ごとに別のデータベースに保存されるため混ざりません。

### 権限の分離（全体管理者と窓口管理者）
- **全体管理者（Super Admin）**: `/admin` で全窓口の作成・削除、システム全体のユーザー管理・SSL・ログイン認証設定、窓口管理者の割り当てを行います。**窓口の管理画面（API キーを含む）には入れません**（その窓口に割り当てられていない限り）。全体管理には、各自のアカウントで本人確認して入ります（共有のパスワードはありません）。
- **窓口の担当者（窓口管理者・App Admin）**: 窓口を作るときに必ず指定する担当者です（メールアドレス、複数可）。自分の窓口の管理画面（`/:app/admin`）に、**各自のアカウントで本人確認して**入ります（Secure LDAP が有効なら本人の Google Workspace のパスワード、無効なら 10 分以内のログイン）。窓口ごとの共通パスワードはありません。担当者は管理画面の **「窓口の担当者」** で担当者を追加し、自分を外して引き継ぐこともできます（最後の 1 人は外せません）。担当者の変更は履歴に残り、全体管理者による変更は強調して表示されます。

> **v0.0.71 へのアップデート後の注意**: 全体管理者は窓口の管理画面に入れません。担当者が未設定の窓口は、全体管理の窓口一覧に「担当者未設定」と表示されるので、「ユーザー管理」で担当者を割り当ててください（全体管理者自身が担当する場合は、自分を割り当てます）。v0.0.70 の窓口の管理者パスワードは廃止しました。ログイン認証が無効（ゲスト）の間は、従来どおり誰でも入れます。

> **v0.1.7 へのアップデート後の注意**: 全体管理の共有の管理者パスワードは廃止しました（保存されていたパスワードも消去されます）。全体管理者は、ヘッダーの「全体管理」から各自のアカウントで本人確認して入ります。`./app.sh admin password` と `.env.prod` の `ASK_DRIVE_ADMIN_PASSWORD` は不要です（残っていても使われません）。

**全体管理者の引き継ぎ**: 初期構築のあと運用責任者に引き継ぐときは、運用責任者を全体管理者に追加（「ユーザー管理」→「メールアドレスで管理者を追加」）したうえで、「ユーザー管理」の自分の行の **「自分の全体管理者権限を外す」** で一般ユーザーに戻れます（全体管理者が 2 人以上いるときだけ表示されます）。`.env.prod` の `ASK_DRIVE_ADMIN_EMAILS` に書いたアドレスは画面からは外せないため、先にその行から削除して `./app.sh restart` してください。

| URL | 内容 |
|---|---|
| `https://<ホスト>:4443/` | 窓口の一覧 |
| `https://<ホスト>:4443/it-support` | 窓口「IT-Support」のチャット |
| `https://<ホスト>:4443/hr` | 窓口「HR」のチャット（作成した場合） |
| `https://<ホスト>:4443/<窓口>/admin` | 窓口の管理（バッチ・ドキュメント・未回答質問・**Drive と API キー/AI 設定**） |
| `https://<ホスト>:4443/admin` | 全体の管理（窓口の追加・編集・削除、ユーザー管理・窓口管理者の割り当て、HTTPS、ローカルモデル、Google ログイン） |

**窓口を追加して API キーやパスワードを設定する手順**
1. 全体の管理（`/admin`）の **「窓口（アプリ）」** タブで、窓口名（例: HR）、URL 名（例: `hr`）、**担当者のメールアドレス**（必須）を入力して「窓口を作成」を押します。
2. 担当者が窓口の管理画面（`/hr/admin`）を開き、本人確認して入ります。担当者の追加・引き継ぎは担当者自身が行えます。
3. 担当者は **「設定」** タブで以下を設定できます：
   - **Google Drive & API キー**: Google Drive のフォルダ・サービスアカウント、および Gemini / Claude / OpenAI の API キー（キーは窓口 DB 内に暗号化されて安全に保存されます）。
   - **窓口アクセスパスワード**: 特定の部署メンバーのみにチャット利用を限定したい場合、窓口アクセスパスワードを有効化できます。
4. 「取り込みのみ実行」または夜間バッチで文書が取り込まれ、専用の窓口として稼働します。

各窓口のチャット画面の左上（「for HR」の部分）から、ほかの窓口へ移動できます。窓口を削除しても、データベースファイルは名前を変えて残ります。

## Google Secure LDAP でのログイン

外部公開の URL がなく Google ログイン（OAuth）を使えない環境でも、社員が **Google Workspace のメールアドレスとパスワード** でログインできます（Google Secure LDAP でパスワードを確認します。AskDrive はパスワードを保存しません）。

1. **Google 管理コンソール**: [アプリ] → [LDAP] → [LDAP クライアントを追加]
   - アクセス権限: 「ユーザー認証情報の確認」と「ユーザー情報の読み取り」を、ログインさせる組織部門に許可
   - 証明書をダウンロード（`Google_YYYY_MM_DD_xxxxx.crt` と `.key` の 2 ファイル）
   - クライアントの「サービスのステータス」をオンにする（反映まで最大 24 時間かかることがあります）
   - Secure LDAP は Business Plus・Enterprise・Education・Cloud Identity Premium などのエディションで使えます
2. **AskDrive**: 全体管理 → 全体設定 → 組織（Google Workspace）→ ログインの方法 → **「Google Secure LDAP でのログイン」**
   - 「LDAP でのログインを有効にする」にチェックすると、サーバー（`ldap.google.com`）・ポート（636）・ベース DN（組織のドメインから）が自動で入ります。通常はそのままで構いません
   - 証明書（.crt）と秘密鍵（.key）を選び、**「接続テスト（入力中の内容で）」** で確認します（保存前でも試せます）
   - 成功したら「保存」。ログイン画面でパスワードを試します
   - アクセス認証情報（ユーザー名・パスワード）は、Google では証明書だけで接続できるため通常は不要です
3. ログイン画面に「メールアドレス」「パスワード」の欄が表示されます（Google ログインも有効なら両方）。メールアドレスは `@` 以降（組織のドメイン）を省略でき、自動で補完されます。Google Workspace に別のドメイン（セカンダリドメイン）がある場合は、`@` 以降まで入力すればそのドメインでもログインできます。
4. **2 回目以降のログインは速くなります。** 一度ログインに成功すると、そのパスワードを 24 時間覚えておき（サーバーのメモリにだけ保存。ハッシュ化し、再起動で消えます）、同じパスワードなら Google に問い合わせずにログインします。そのため、Google Workspace でパスワードを変えたりアカウントを停止したりしても、反映されるのは最長で翌日です（新しいパスワードでログインすると、その時点で入れ替わります）。全体管理・窓口の管理画面に入るときの本人確認は、常に Google に問い合わせます。
5. 以後、管理者や窓口の担当者のメールアドレスを入力する欄では、2 文字以上入力するとディレクトリから候補（名前とメールアドレス）が表示されます。保存時には、ディレクトリに存在しないアドレスをはじきます（タイポ防止）。

Google ログイン（OAuth）は、同じ「ログインの方法」の **「Google OAuth（ログイン / Drive 同期）」** で個別に有効 / 無効を切り替えられます。ここのクライアント ID / シークレットは、窓口の Google Drive 同期の OAuth と共通です。**ログインには使わず、Drive 同期にだけ OAuth を使う** こともでき、その場合はクライアント ID / シークレットを保存し、「Google ログインを有効にする」をオフのままにします（Drive 同期の認可は、窓口の管理画面に入っている窓口管理者が行います）。Google ログインも Secure LDAP も **既定は無効** です。設定した方を有効にすると、その方法だけがログイン画面に表示されます。無効にしても認証情報は残り、Drive 同期の OAuth 連携には影響しません（`./app.sh auth oauth on|off` でも可）。

> **注意**: LDAP でのパスワード確認には Google の 2 段階認証がかかりません。そのため、同じアカウントで 5 分間に 5 回失敗するとそのアカウントを 15 分、同じ接続環境（ブラウザ）から 24 時間に 10 回失敗するとその接続環境を 24 時間ロックします。社内の NAT で全員が同じ IP でも、ロックされるのは失敗したブラウザだけです。ロック中の一覧と「解除」ボタンは同じ設定画面にあります。証明書の有効期限（3 年）は設定画面に表示されます。期限前に管理コンソールで再発行して登録し直してください。

## 端末の電子証明書によるアクセス制限

AskDrive が発行した電子証明書をインストールした端末（ブラウザ）だけが、ログイン画面を含むすべての画面に入れるようにできます。誰であるかは従来どおりログインで確認し、証明書は「配布した端末であること」を確かめる追加の対策です。設定は全体管理 → 全体設定 → **「端末の電子証明書によるアクセス制限」** です。

1. **グループを追加**（例: 経理部）し、**「証明書を発行…」** を押します。**メモ**（任意。例: 受付の PC）、**有効期限**（既定は 1 年後）、**パスワード**（任意。空欄なら 16 文字を自動生成。指定する場合は 8〜64 文字の半角英数字・記号）を入れて「発行する」を押すと、パスワードが表示され、10 分間、配る相手の端末に合わせた形式（Windows 用 .pfx、macOS 用 .p12、iPhone / iPad 用 .mobileconfig、Android 用 .p12）をダウンロードできます。いずれも端末の管理者権限なしでインストールできます。パスワードはファイルとは別の手段で伝えてください。
   - 証明書は、ブラウザやキーチェーンで **「AskDrive（グループ名）」**（メモを入れた場合は「AskDrive（グループ名 / メモ）」）という名前で表示されます。
   - あとから一覧の **「再ダウンロード」** で、同じ証明書を同じパスワードで取得し直せます（失効・期限切れのものを除く）。発行した証明書とパスワードは暗号化して保存しています。
2. 各端末で .p12 を開き、パスワードを入力してインストールします（下の「証明書のインストール手順」）。
3. 社内 LAN からは証明書なしで使わせる場合は、**「社内 LAN の IP アドレス・範囲」** に社内のアドレス（例: `192.168.0.0/16`）を設定します。ここからの接続は、強制中でも証明書なしでログイン画面・ログイン後の画面に入れます（ログインは必要です）。リバースプロキシ経由の構成では、「ポートとリバースプロキシ」にプロキシを登録してください（しないと全員が社内 LAN からに見えます）。
4. **「監視」** にします。ブラウザが証明書の選択を求めたら AskDrive の証明書を選びます。この画面の「この接続の証明書: 有効」で確認でき、証明書なしでアクセスしたユーザーが一覧されます。
5. 全員の準備ができたら **「強制」** にします（有効な証明書のある接続、社内 LAN、またはサーバー自身からだけ操作できます）。監視中の「証明書なしでアクセスしたユーザー」には、社内 LAN からのアクセスは含まれません。以後、証明書のない端末には案内ページが表示されます。

- 交換は、同じグループで新しい証明書を発行して配り、入れ替えが済んだら古い証明書を「失効」させます。漏洩した場合はすぐに失効させてください。
- HTTPS で直接つなぐ構成が前提です（リバースプロキシで TLS を終端すると、プロキシ経由では証明書が届きません）。
- 締め出された場合は、サーバー上で `./app.sh mtls off` を実行するか、サーバー自身（`https://localhost:4443/`）から開いてください。サーバー上で証明書を発行する `./app.sh mtls issue <グループ> <ファイル.p12> [--expires YYYY-MM-DD] [--label メモ] [--password パスワード]` もあります。

### 証明書のインストール手順（配布される側）

> **初心者向けの詳しい手順書**: [CLIENT_CERT_GUIDE.md](CLIENT_CERT_GUIDE.md)（画面に沿った手順、うまくいかないとき、よくある質問、証明書の削除。配布される方にそのまま渡せます）

証明書ファイルとパスワードは管理者から配布されます（お使いの端末に合わせた形式: Windows は .pfx、macOS と Android は .p12、iPhone / iPad は .mobileconfig）。いずれも端末の管理者権限なしでインストールできます。 証明書のない端末で AskDrive を開くと表示される案内ページにも、同じ手順が載っています。OS のメニュー名はバージョンや機種で異なることがあります。

**Windows（Chrome / Edge）**

1. 配布された .pfx ファイルをダブルクリックします（「証明書のインポート ウィザード」が開きます）。
2. 「保存場所」は「現在のユーザー」を選び、「次へ」を押します（「ローカル コンピューター」は管理者権限が必要なので選びません）。
3. ファイル名はそのまま「次へ」。パスワードの欄に、別途伝えられたパスワードを入力して「次へ」を押します（「このキーをエクスポート可能にする」にはチェックしないでください）。
4. 「証明書の種類に基づいて、自動的に証明書ストアを選択する」のまま「次へ」→「完了」を押します。
5. ブラウザ（Chrome / Edge）をすべて閉じてから開き直し、AskDrive を開きます。証明書の選択画面が出たら「AskDrive（グループ名）」を選んで「OK」を押します。

**macOS（Safari / Chrome / Edge）**

1. 配布された .p12 ファイルをダブルクリックします（「キーチェーンアクセス」が開きます）。
2. 追加先のキーチェーンは「ログイン」を選び（「システム」は管理者権限が必要なので選びません）、別途伝えられたパスワードを入力します。
3. ブラウザを終了してから開き直し、AskDrive を開きます。証明書の選択画面が出たら「AskDrive（グループ名）」を選びます。
4. 「キーチェーンの使用を許可しますか」と表示されたら、Mac のログインパスワードを入力して「常に許可」を押します。

**iPhone / iPad（Safari）**

1. .mobileconfig ファイルを AirDrop・メール・「ファイル」アプリなどで端末に送り、タップして開きます（「プロファイルがダウンロードされました」と表示されます）。
2. 「設定」アプリを開き、上部の「プロファイルがダウンロード済み」（または「一般」→「VPN とデバイス管理」）をタップします。
3. 「インストール」を押し、端末のパスコード、続けて別途伝えられた証明書のパスワードを入力して、インストールを完了します（「未検証」と表示されますが、AskDrive が作成したプロファイルのため問題ありません）。
4. Safari で AskDrive を開きます。証明書の選択を求められたら「AskDrive（グループ名）」を選びます。

**Android（Chrome）**

1. .p12 ファイルを端末に保存します（メールの添付などからダウンロード）。画面ロック（PIN・パターン等）が未設定の場合は、インストール時に設定を求められます。
2. 「設定」→「セキュリティとプライバシー」→「その他のセキュリティ設定」→「暗号化と認証情報」→「証明書のインストール」→「VPN とアプリのユーザー証明書」を開きます（メニューの名前は機種や Android のバージョンで異なります。設定の検索で「証明書」と探すと見つかります）。
3. 保存した .p12 ファイルを選び、別途伝えられたパスワードを入力します。証明書の名前は「AskDrive」など分かりやすいものにします。
4. Chrome で AskDrive を開きます。証明書の選択を求められたら「AskDrive」を選んで「選択」を押します。

**Firefox（Windows / macOS）**

1. Firefox は OS とは別に証明書を管理します。「設定」→「プライバシーとセキュリティ」→「証明書」の「証明書を表示...」を開きます。
2. 「あなたの証明書」タブで「インポート...」を押し、.p12 ファイルを選んで、別途伝えられたパスワードを入力します。
3. Firefox を開き直し、AskDrive を開きます。証明書の選択を求められたら「AskDrive（グループ名）」を選びます。

**うまくいかないとき**

1. インストール後も表示が変わらない場合は、ブラウザを完全に終了してから開き直してください（ブラウザは証明書の選択を覚えています）。
2. 証明書の選択画面で、別の証明書を選んでしまった場合も、ブラウザを開き直すと選び直せます。
3. 証明書を新しいものに交換した場合は、古い証明書を削除してから開き直してください（Windows:「ユーザー証明書の管理」、macOS:「キーチェーンアクセス」、iPhone:「VPN とデバイス管理」、Android:「ユーザー認証情報」）。
4. 「失効しています」「有効期限が切れています」と表示された場合は、新しい証明書を管理者に依頼してください。

## HTTPS（SSL）

v0.0.45 以降、AskDrive の通信はすべて HTTPS で暗号化されます。

| ポート（既定） | 役割 |
|---|---|
| **4443** | HTTPS。アプリ本体（自己署名証明書が既定） |
| 4000 | HTTP。HTTPS へ転送。ただし「ポートとリバースプロキシ」で指定したプロキシからは HTTP のまま応答 |

ポート番号は、管理画面の設定タブ **「HTTPS（SSL 証明書）」→「ポートとリバースプロキシ」** で変更できます（ほかのソフトとポートが競合したとき用）。変更すると待ち受けを再起動し、新しいポートで起動できなければ元に戻します。v0.0.68 で HTTP の 4080 は廃止し、4000 にまとめました。

- **初回起動時**に自己署名証明書を自動で作成します（`localhost`・PC のホスト名・LAN の IP アドレス向け、`ssl/active/` に保存。秘密鍵は所有者のみ読み取り可）。自己署名証明書のため、ブラウザに「この接続ではプライバシーが保護されません」等の警告が出ます。社内検証中は「詳細」から続行してください。
- **独自の証明書**（認証局が発行した証明書）は、管理画面の設定タブ **「HTTPS（SSL 証明書）」** で設定します。
  1. 証明書・秘密鍵（パスフレーズなし）・中間証明書（任意）の PEM ファイルを選び、公開するホスト名を入力して **「検証する」** を押します。形式、証明書と鍵の対応、有効期限、中間証明書のつながり、ホスト名を確認し、実際に TLS 接続を試します。
  2. 検証に成功したら **「保存して適用」** を押します。証明書を保存して HTTPS を再起動し、数秒後にページが自動で再接続します。新しい証明書で起動できなかった場合は、自動的に元の証明書へ戻します。
  3. 独自の証明書を設定すると **HSTS** が有効になります（自己署名証明書の間は送りません）。「自己署名証明書に戻す」で元に戻せます。
- **リバースプロキシ（Cloudflare Tunnel・nginx 等）で HTTPS を終端する場合**は、「ポートとリバースプロキシ」にそのプロキシの IP（例: 同じマシンなら `127.0.0.1`）を登録し、プロキシから `http://<ホスト>:4000` に中継させてください。登録した IP からの HTTP だけを受け付け、プロキシが付ける `X-Forwarded-Proto/Host/Port`・`X-Forwarded-For`（Cloudflare の `CF-Connecting-IP`）を信頼します（Google ログインのリダイレクト URI を公開 URL で組み立て、ロックや記録には利用者の実際の IP を使います）。それ以外からの HTTP は HTTPS に転送します。HSTS はプロキシ側で付けてください。プロキシから `https://<ホスト>:4443` に中継しても構いません。
- 以前の `ASK_DRIVE_TRUST_FORWARDED`・`ASK_DRIVE_LEGACY_REDIRECT` は廃止しました。`ASK_DRIVE_TRUST_FORWARDED=true` を使っていた場合は、プロキシの IP を管理画面で登録してください。
- 設定を誤って入れなくなった場合は、サーバー上で `./app.sh network status`（確認）、`./app.sh network proxy-off`（プロキシの指定を解除）、`./app.sh network ports-reset`（ポートを 4000 / 4443 に戻して再起動）を実行します。
- HTTPS を使わない従来の HTTP 運用に戻すには `.env.prod` に `ASK_DRIVE_SSL=false` を設定して再起動します。
- **Google ログイン**（OAuth）のリダイレクト URI は `https://<ホスト名>:4443/auth/google/callback` になります。Google Cloud Console に登録してください。

## 初期設定と Google 連携手順

AskDrive は、全社公開マニュアルなどの Google Drive フォルダを同期する **「同期専用 Google アカウント」** と、チャットを利用する **「社員アカウント」** の 2 種類のアカウント形態をサポートしています。

社員アカウントは**全員が一般ユーザーとしてログイン**します。常時の管理者アカウントはありません。管理操作が必要なときだけ、許可されたアカウント（全体管理者）が**本人確認**をしてそのセッションの間だけ昇格します（`sudo` と同じ考え方です。共有の管理者パスワードはありません）。

```
[ Google Drive マニュアルフォルダ ]
               │ (夜間自動同期 / 同期専用アカウントで認可)
         ┌─────▼─────┐
         │  AskDrive │ ◄── LAN 公開 (https://<ホスト>:4443)
         └─────▲─────┘
               │ (Google ログイン / @company.com ドメイン限定)
               ▼
        [ 一般ユーザー ]  ← 全員ここから。チャットのみ
               │
               │  昇格可能に指定されたアカウントのみ
               │  「全体管理」で本人確認（LDAP のパスワード / 直近のログイン）
               ▼
     [ 昇格中セッション ]  ← 管理画面・設定・Drive連携・ユーザー管理
               │
               ├─ 「管理者権限を解除」で即降格
               └─ 30 分（既定）で自動失効
```

| | 同期専用 Google アカウント | 一般ユーザー | 昇格中の管理者 |
|---|---|---|---|
| 目的 | Drive フォルダの読み取り | チャット利用 | 運用・設定 |
| 件数 | 1 件 | 人数分 | そのつど・一時的 |
| チャット (`/`) | — | ○ | ○ |
| 管理画面 (`/admin`) | — | × | ○ |
| LLM プロバイダ・API キーの変更 | — | × | ○ |
| Drive 連携・バッチ実行 | — | × | ○ |
| 昇格可能アカウントの追加・削除 | — | × | ○ |

**昇格の 3 条件** — 次のすべてを満たしたときだけ管理画面に入れます。

1. 許可ドメインの Google アカウントでログイン済みであること
2. そのアカウントが「昇格可能」に指定されていること
3. 本人確認ができること（Secure LDAP が有効なら本人の Google Workspace のパスワード、無効なら 10 分以内のログイン）

> 昇格可能アカウントは、初期セットアップ時に入力したメールアドレス（`.env.prod` の `ASK_DRIVE_ADMIN_EMAILS`）で決まります。未設定の場合は**最初にログインした利用者**に自動で付与されます。以降は管理画面の「ユーザー管理」タブで追加・削除できます。

> 昇格の成功・失敗・解除はすべて記録され、管理画面の「昇格履歴」タブで確認できます。全体管理者から外せば、その人はすぐに入れなくなります。

### ステップ 1: Google Cloud Console での事前準備（5分）

> AskDrive は **Google Workspace（会社・組織契約）** と **個人 Google アカウント（@gmail.com）** の両方に対応しています。
> このステップの OAuth クライアントはログインおよび Drive 同期で利用します。

1. **[Google Cloud Console](https://console.cloud.google.com/)** に Google アカウント（Workspace 管理者アカウント または 個人 Google アカウント）でログインします。
2. **Google Drive API の有効化**:
   - `[API とサービス]` ➔ `[ライブラリ]` を開き、**`Google Drive API`** を検索して **「有効にする」** をクリックします。
3. **OAuth 同意画面の設定**:
   - `[API とサービス]` ➔ `[OAuth 同意画面]` を開きます。
   - **User Type（ユーザーの種類）**:
     - **Google Workspace（会社・組織）**: **「内部 (Internal)」** を選択（自社 Google Workspace ドメインのユーザーのみアクセス許可、審査不要）。
     - **個人 Google アカウント（@gmail.com 等）**: **「外部 (External)」** を選択し、同意画面の作成後に **「テストユーザー」** に利用する Gmail アドレス（ログインや Drive 同期で使うアカウント）を追加します（公開ステータスが「テスト中」の場合に必要）。
   - アプリ名（例: `AskDrive`）、ユーザーサポートメール、開発者連絡先メールを入力して保存します。
   - スコープに `.../auth/drive.readonly`、`.../auth/userinfo.email`、`.../auth/userinfo.profile`、`openid` を追加します。
     - `drive.readonly` は同期専用アカウント用、残りは社員ログイン用です。
4. **OAuth 2.0 クライアント ID の作成**:
   - `[API とサービス]` ➔ `[認証情報]` ➔ `[+ 認証情報を作成]` ➔ **「OAuth クライアント ID」** を選択します。
   - **アプリケーションの種類**:
     - **「デスクトップ アプリ」**（Drive 同期メインの場合、リダイレクト URI 登録不要で最も簡単・推奨）
     - または **「ウェブ アプリケーション」**（ブラウザからの Google ログインを使う場合）
   - **「ウェブ アプリケーション」の場合の承認済みのリダイレクト URI**:
     - AskDrive はアクセスされた URL のホスト名をそのまま Google への `redirect_uri` として使います。**ブラウザが実際にアクセスした URL と完全に一致するリダイレクト URI が登録されていないと、Google 認証は失敗します。**
     - **⚠️ 生の IP アドレス（`http://192.168.x.x:...`）や `.local`（mDNS）ホスト名は Google 側で拒否されます。** `localhost` 以外で LAN からアクセスさせたい場合は、**正式な公開 TLD（`.com` / `.net` など）を持つホスト名**が必須です（社内 DNS や各端末の `hosts` ファイルで、そのホスト名を稼働機の LAN IP に向ければ、実際にインターネットへ公開する必要はありません）。
     - 管理者が初期設定を `localhost` で行い、LAN 経由でアクセスする場合は、**両方**を登録してください（Google は 1 つの OAuth クライアントに複数のリダイレクト URI を登録できます）:
       ```text
       https://localhost:4443/auth/google/callback
       https://<自社ドメインのサブドメイン>:4443/auth/google/callback
       ```
       （例: `https://ask-drive.company.com:4443/auth/google/callback`。v0.0.45 以降は HTTPS のため、以前 `http://…:4000/…` で登録していた場合は HTTPS の URI を追加してください）
     - 複数のホスト名からアクセスされ得る場合は、その分だけ URI を追加登録してください。
     - **社員ログインと Drive 同期認可は同じコールバック URI を共用します。** 用途ごとに別の URI を用意する必要はありません。
   - **「作成」** をクリックし、表示された **「クライアント ID」** と **「クライアント シークレット」** を控えます。

> **トラブルシューティング**
>
> - **「Error 400: invalid_request」「device_id and device_name are required for private IP」** → リダイレクト URI（および実際にブラウザでアクセスしている URL）が生の IP アドレスになっています。上記の通り、公開 TLD を持つホスト名に変更してください。
> - **「エラー 400: redirect_uri_mismatch」** → 今アクセスしている URL（アドレスバーの `http://...`）と完全に一致するリダイレクト URI が Google Cloud Console に登録されていません。追加登録してください。
> - ブラウザのコンソールに出る `navigate event to "..." failed because you are redirecting across live_sessions. A full page reload will be performed instead` という警告は、チャット画面と管理画面が別の LiveView セッションであることによる**無害な**メッセージです（自動的に通常のページ遷移にフォールバックするだけで、アクセス自体は失敗しません）。ログインできない場合の原因は、ほぼ常に上記 2 つのいずれかです。

### ステップ 2: ログインと管理者への昇格

1. ブラウザで `https://<Google Cloud Console に登録したホスト名>:4443/` を開きます。未ログインの場合はログイン画面が表示されます。
2. **「Google でログイン」** をクリックし、初期セットアップで指定したアカウントでログインします。この時点では一般ユーザーです。
3. ヘッダ右側（En / Ja の切り替えのすぐ左）の **「全体管理」** をクリックし、本人確認をします（Secure LDAP が有効なら本人の Google Workspace のパスワードを入力。無効なら 10 分以内にログインしていればそのまま入れ、古ければログインし直します）。
4. 昇格に成功すると全体の管理画面が開き、ヘッダの同じ位置に「管理者モード（残り 30 分）｜リリース｜全体管理」のまとまりが表示されます。ヘッダ左側の **「（窓口名）の管理」**（例: 「IT-Support の管理」）は、その窓口だけの管理画面です（窓口の担当者に表示されます）。
5. 作業が終わったら **「管理者権限を解除」** で降格してください（放置しても既定 30 分で自動的に降格します）。

> OAuth クライアント ID / シークレットを初期セットアップで入力していない場合は、`.env.prod` に `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `ASK_DRIVE_ADMIN_EMAILS` を追記して `./app.sh restart` してください。


#### ログイン認証の有効化（POC → 本運用）

初期状態は **ログイン認証が無効（ゲスト・POC）** です。チャットも管理画面（全体管理を含む）も、LAN 上の誰でもログインなしで使えます（起動ログに `[!] 認証: 無効` と表示され、画面の上部にも赤い帯で警告が出ます）。ゲストは準備期間（お試し）用です。ログインの方法を設定したら、早めにログイン認証を有効にしてください。ログインの方法を設定すると、赤い帯が「ログイン認証を有効にする」ボタン付きの表示に変わります。ログイン認証は自動では有効にならないので、利用者への案内と合わせて切り替えてください。

ログインの方法（**Google Secure LDAP** または Google ログイン）を設定したら、次の手順でログイン必須に切り替えます。

1. 全体管理 → 全体設定 → **「ログイン認証」**
2. 管理者のメールアドレス（複数可・カンマ区切り。有効化後にこのいずれかでログインして昇格します）を確認し、「ログイン認証を有効にする」。初回セットアップで指定した全体管理者が、あらかじめ入力されています
3. ログイン画面に移るので、そのアカウントでログインし、「全体管理」から本人確認して入ります

有効にすると、窓口一覧・チャットを含むすべての画面でログインが必要になり、管理画面はさらに本人確認が必要になります。再起動は不要です。ゲストの間は、すべての画面の上部に赤い帯で「ログイン認証が無効です」と表示されます。無効に戻すのも同じカードから行えます。

管理者はあとから何人でも追加できます: 全体管理 → **ユーザー** →「メールアドレスで管理者（昇格可）を追加」（まだログインしたことのない人も追加できます）。

**締め出されたとき**（LDAP が使えなくなった、管理者アカウントでログインできない等）は、サーバー上で次を実行します（再起動なしで反映）:

```bash
./app.sh auth status              # ログイン認証・LDAP・管理者アカウントの状態
./app.sh auth disable             # ログイン認証を無効に戻す（ゲスト・POC）
./app.sh auth ldap off            # LDAP でのログインだけを無効にする
./app.sh auth oauth off           # Google ログイン（OAuth）だけを無効にする
./app.sh auth enable you@company.com other@company.com   # 有効にし、それらのアカウントを管理者に昇格可能にする
```

> `.env.prod` に `ASK_DRIVE_DISABLE_AUTH` を書いている場合は、それが優先され画面やコマンドでは切り替わりません。画面で切り替えるには、その行を削除して `./app.sh restart` してください。

### ステップ 3: Web 管理画面での設定

1. ブラウザで `https://<Google Cloud Console に登録したホスト名>:4443/admin?tab=settings` を開きます（昇格中のみ）。
2. **LLM プロバイダ設定** を確認・変更します:
   - **回答生成プロバイダ / モデル**: `ollama` + `qwen3:4b`（既定）、または `anthropic` + `claude-sonnet-5` など
   - **埋め込みプロバイダ / モデル / 次元**: 既定は `ollama` + `bge-m3` + `1024`
   - **API キー**: 外部 API を選んだ場合に入力。保存後は末尾 4 文字のみ表示されます（空欄で保存すると既存値を維持）
   - **「接続テスト」** で疎通を確認します
   - **埋め込みモデルまたは次元を変更すると全件再インデックスが必要です。** 確認ダイアログが出ます
3. **システム・OAuth 設定** を入力して **「設定を保存」** をクリックします:
   - **OAuth クライアント ID / シークレット**: Google Cloud Console で取得した値を貼り付け
   - **許可 Google Workspace ドメイン**: 会社・組織で特定ドメインに制限する場合は入力（例: `company.com`）。個人利用（@gmail.com）や制限なしの場合は空欄。
4. **Google Drive 同期の設定** — 窓口の「設定」の **「Google Drive 同期設定」** カードで、認証の方式を選び、**「同期するフォルダ」**（取り込み対象の共有フォルダの URL または ID）を入力して保存し、**「同期テスト」** で確認します。同期テストは、認証とフォルダの読み取りを確認し、同期の対象になるファイルの件数と例を表示します（取り込みはしません）。**Google アカウント認証**（実在の Google アカウントの権限で同期）を使う場合:
   1. **最初に 1 回だけ**: Google Cloud Console で OAuth クライアントを作ります（Google Drive API を有効化 → OAuth 同意画面を作成（組織なら「内部」、個人なら「外部」＋テストユーザー追加） → 「OAuth クライアント ID」を種類 **「デスクトップ アプリ」** で作成。リダイレクト URI の登録は不要）。クライアント ID / シークレットを **全体設定の「Google OAuth（ログイン / Drive 同期）」** に保存すれば、すべての窓口で使えます（「Google ログインを有効にする」はオフのままで構いません）。窓口のカードの「OAuth クライアント（初回のみ）」に入れて、その窓口だけで使うこともできます。
   2. **窓口ごと**: 「Google アカウント」に同期に使うアカウントを入れて **「接続」** を押し、Google の画面でログインして「許可」します。
      - Google の画面は別ウィンドウで開きます。**AskDrive のサーバーの PC 上のブラウザ**（`https://localhost:4443/`）で操作した場合は、別ウィンドウに「Google Drive と接続しました」と表示され、管理画面も自動で「接続中」になります。
      - **別の PC のブラウザ**で操作した場合は、許可後に別ウィンドウに「このサイトにアクセスできません」などと表示されるので（正常です）、そのページの **アドレス**（`http://localhost:4000/auth/google/callback?state=…&code=…`）をコピーしてカードの欄に貼り付けます。貼り付けると自動で保存されます。
      - **会社ドメインなどのホスト名**（例: `https://askdrive.<会社のドメイン>:4443/`。社内 DNS だけで引ける名前でも可）で開いている場合は、許可すると AskDrive に直接戻り、貼り付けなしで保存されます（ウェブ アプリケーション型のクライアントに、画面に表示されるリダイレクト URI の登録が必要です）。
      - 「接続」の近くに、そのボタンが使う **OAuth クライアント ID とリダイレクト URI** が表示されます。Cloud Console の登録内容と照らし合わせてください。
      - Google に「**エラー 400: redirect_uri_mismatch**」と表示された場合は、OAuth クライアントの種類が「ウェブ アプリケーション」です。Google Cloud Console でそのクライアントの「承認済みのリダイレクト URI」に `http://localhost:4000/auth/google/callback` を追加してください（サーバーの PC 上からでも別の PC からでも、この 1 つで足ります）。全体設定の「接続テスト」で、クライアント ID / シークレットが正しいかを確認できます。
   3. 「同期するフォルダ」を保存し、「同期テスト」で確認します。

   #### 方式 A: サービスアカウント（推奨・URL 依存なし）

   ブラウザでの認可が不要なため、ステップ 1 で説明した redirect_uri の制約（生の IP・`.local` の拒否）を一切受けません。LAN のどの IP・ホスト名からアクセスしても Drive 同期には影響しません。

   1. [Google Cloud Console の「サービスアカウント」](https://console.cloud.google.com/iam-admin/serviceaccounts)を開き、新しいサービスアカウントを作成します（ロールの付与は不要です）。
   2. 作成したサービスアカウントの **「キー」** タブから **「鍵を追加」→「新しい鍵を作成」→ JSON** を選び、JSON ファイルをダウンロードします。
   3. Google Drive で同期対象のフォルダを開き、サービスアカウントのメールアドレス（`...@...iam.gserviceaccount.com`。JSON ファイル内の `client_email`）を**閲覧者として共有**します。**社内限定の共有ドライブで「outside of <組織名>」と表示されて追加できない場合、この手順は飛ばし、下の「ドメイン全体の委任」に進んでください**（委任ではサービスアカウントを共有に追加しません）。
   4. AskDrive の管理画面で **「サービスアカウント」** タブを選び、ダウンロードした JSON ファイルの中身をそのまま貼り付けて **「保存」** → **「接続テスト」** で疎通を確認します。接続テストはトークンの取得に加えて、同期フォルダを実際に読み取れるかまで確認します。

   ##### 社内限定の共有ドライブを同期する場合（ドメイン全体の委任）

   共有ドライブが「組織内のユーザーのみアクセス可」に設定されていると、手順 3 で次のように表示され、サービスアカウントを共有に追加できません（サービスアカウントは Google 上では常に組織外のアカウントです）。

   > `...@...iam.gserviceaccount.com is outside of <組織名>. Only people inside <組織名> can access files in this shared drive.`

   この場合は、サービスアカウントに **社内ユーザーとして** Drive を読ませます（ドメイン全体の委任）。共有ドライブを社外に開く必要はありません。**共有ドライブのメンバーに追加するのはサービスアカウントではなく、アクセスユーザー（社内ユーザー）です。**

   1. **アクセスユーザー（社内ユーザー）を決めます。** 同期対象のフォルダ（共有ドライブ）を閲覧できる Workspace ユーザーです。個人ではなく同期専用のアカウント（例: `askdrive-sync@example.com`）を推奨します。AskDrive が読み取るのはこのユーザーが見られるファイルに限られ、スコープは読み取り専用（`drive.readonly`）です。
   2. **Google Workspace の特権管理者に委任を許可してもらいます。** [Google 管理コンソール](https://admin.google.com/) →「セキュリティ」→「アクセスとデータ管理」→「API の制御」→「ドメイン全体の委任を管理」→「新しく追加」で、次を登録します。
      - **クライアント ID**: JSON キーの `client_id`（数字 21 桁程度。管理画面のサービスアカウント設定欄にも表示されます）
      - **OAuth スコープ**: `https://www.googleapis.com/auth/drive.readonly`

      反映まで数分、長いと最大 24 時間かかることがあります。
   3. **AskDrive にアクセスユーザーを設定します。** 管理画面のサービスアカウント設定欄の **「アクセスユーザー」** にメールアドレスを入力して **「保存」**（JSON キー欄は空欄のままで既存のキーが維持されます）→ **「接続テスト」**。CLI の場合は `./app.sh drive service-account --subject askdrive-sync@example.com` です。

   接続テストで表示されるエラーと対処:

   | 表示 | 原因と対処 |
   |---|---|
   | 「ドメイン全体の委任が許可されていません」 | 手順 2 が未登録・反映待ち、またはクライアント ID / スコープの誤り |
   | 「アクセスユーザー … でトークンを取得できませんでした」 | メールアドレスの誤り、または停止中・存在しないユーザー |
   | 「… には同期フォルダの閲覧権限がありません」 | アクセスユーザーを共有ドライブのメンバーに追加する |
   | ファイル別ログに「ダウンロードが禁止されています (cannotDownloadFile)」 | 閲覧者にダウンロードが禁止されている。共有ドライブの設定で「閲覧者と閲覧者（コメント可）にファイルのダウンロード、印刷、コピーを許可」を有効にするか、アクセスユーザーを **投稿者** 以上にする（AskDrive のスコープは `drive.readonly` なので、投稿者にしても書き込みはしません） |

   #### 方式 B: OAuth（従来方式・redirect_uri の制約あり）

   1. **「OAuth（専用アカウント）」** タブを選びます。
   2. **「専用 Google アカウントで認可」** をクリックし、対象フォルダの閲覧権限を持つ同期専用 Google アカウントで認可を完了します。
   3. この方式は、今アクセスしているブラウザの URL（ホスト名）がステップ 1 で登録したリダイレクト URI と完全に一致している必要があります。

5. **同期の開始**:
   - 深夜 0:00〜7:00（稼働機のローカル時刻）の夜間枠に入ると、夜間バッチ（同期・取り込み・QA 生成）が自動で1回実行されます。実行中のバッチは **8:00 まで** 処理を続けます（「バッチの打ち切り時刻」で変更可）。夕方や夜に手動で実行しても、その夜の自動実行は行われます（手動実行は自動実行の代わりになりません）。開始時刻は管理画面の「バッチ開始時刻」で変更できます。
   - 手動で実行する場合は管理画面トップのボタンを使います。
     - **取り込みのみ実行**（日中はこちら）: Drive の同期と取り込み（本文抽出・埋め込み）だけを行います。数分で終わり、実行中もチャットは通常どおり使えます。取り込んだ文書は、終了直後からチャットの「関連しそうな箇所」に表示されます。
     - **フル実行（QA 生成あり）**: QA 生成まで行います。ローカルモデルでは数時間かかり、その間チャットは原文検索のみになるため、通常は夜間の自動実行に任せてください。
   - チャットでは、検索で見つかった抜粋をもとに **AI による要約** を表示し、その下に番号付きの **引用元**（文書名・ページ・「Drive で開く」・抜粋）を並べます。要約中の [1] などをクリックすると該当する引用元に移動します。要約には管理画面の **「チャット要約プロバイダ / モデル名」** を使います（空欄なら夜間バッチと同じ「回答生成プロバイダ / 生成モデル名」）。夜間の QA 生成はローカル（Ollama）のまま、チャットだけを Gemini などのクラウド API にして高精度・高速にできます。クラウドを選ぶと、質問と検索された抜粋が API 提供元に送信され、その API キーの設定が必要です。ローカルでは1回答に数十秒かかるため、生成しながら表示します。管理画面の設定「チャットで検索結果の AI 要約を表示する」で無効にできます。
     - **推奨モデル（ローカル）:** チャット要約には、推論（思考）をしない `qwen3:4b-instruct-2507-q4_K_M` をおすすめします。`qwen3:4b` と同じサイズで、思考の待ち時間がなく、指示（日本語・字数）に従いやすくなります。v0.0.43 以降は、アップデート時にチャット要約モデルがこのモデルに自動で切り替わり（空欄だった場合）、アプリが取得します。夜間バッチの「ローカル LLM のモデル名」にも使えます（QA 生成も速くなります）。
     - **モデルの取得はアプリが行います。** Ollama はアプリ専用のため、ターミナルの `ollama pull` は使えません。設定で使うモデルは、アプリの起動時（アップデート後を含む）と設定の保存時に自動で取得されます。Ollama を使う窓口の管理画面の設定タブ **「ローカルモデル（Ollama）」**（外部 API だけの窓口と全体設定には表示されません）で、必要なモデルの状態（取得済み / 未取得 / 取得中）を確認でき、任意のモデルを名前で取得できます。CLI から操作する場合は `./app.sh ollama pull <モデル名>` / `./app.sh ollama list` を使います。
     - 要約は日本語の質問なら日本語で 250 字程度（上限 300 字）に収めます。`qwen3` のような推論モデルの思考過程は要約には出さず、「AI の思考過程を表示」を開いたときだけ見られます。推論しないモデル（例: 同じ系列の instruct 版）を「チャット要約モデル名」に設定すると、思考の待ち時間がなくなり速くなります。
     - 夜間バッチで生成した QA は、質問との類似度が **「QA 即答（Tier 1）の類似度しきい値」**（既定 0.90）以上のときだけ即答に使われます。それ未満の質問は、抜粋と AI 要約で回答します。
     - **Gemini API を使う手順:**
       1. [Google AI Studio](https://aistudio.google.com/) で API キーを発行します（本番運用は有料枠を推奨。無料枠はレート制限が厳しく、夜間バッチで待ち時間が増えます）。
       2. 管理画面の設定で「Gemini API キー」を入力します。
       3. チャットだけを Gemini にする場合: 「チャット要約プロバイダ」を Gemini、「チャット要約モデル名」に使うモデル名（例: Flash 系のモデル）を設定します。推論はオフ、回答はストリーミング表示になります。
       4. 夜間バッチも Gemini にする場合: 「夜間バッチ（QA 生成）の実行方法」をクラウド API、「クラウド API プロバイダ」を Gemini、「クラウド API のモデル名」を設定します。
       5. 「接続テスト」で疎通を確認します。429（レート制限）は Gemini が指定する待ち時間に従って自動で再試行します。
     - **夜間バッチ（QA 生成）もクラウドにできます。** 管理画面の「夜間バッチ（QA 生成）の実行方法」で「ローカル LLM」と「クラウド API」を切り替えます。ローカル用・クラウド用のプロバイダとモデル名はそれぞれ保存されるので、切り替えのたびに入れ直す必要はありません。クラウドは QA の精度と速度が上がりますが、全チャンクの本文が API 提供元に送信され従量課金になります（差分取り込みのため、2回目以降は変更分のみ）。
     - ローカルで遅い場合、メモリに余裕があれば `.env.prod` に `OLLAMA_MAX_LOADED_MODELS=2` を設定すると、埋め込みモデルと生成モデルを両方常駐させて入れ替えを避けられます。
   - チャットの抜粋には、PDF の場合 **ページ番号（p.N）** が表示され、「Drive で開く（p.N）」はそのページを指定して開きます。Drive のビューアがページ指定を無視した場合は先頭から開くので、ビューアのページ欄で N を指定してください。
   - 管理画面トップの **「夜間バッチの自動実行と履歴」** で、昨夜の自動実行が行われたか（手動か自動か、開始時刻、所要時間、結果）と次回の予定を確認できます。履歴の行をクリックすると、そのバッチのファイル別ログを表示します。状態の「中断（再起動）」は、実行中にデプロイ等でアプリが再起動されたことを表します（同じ夜間枠なら自動で再実行されます）。
   - 実行中は **進捗**（全体の目安 %、現在のステップと「完了 / 全体」、処理中のファイル、残り時間の推定）を表示し、5 秒ごとに更新します。長い PDF では「埋め込み 64 / 186 チャンク」のようにファイルの中の進み具合も表示します。
   - 実行中のバッチは画面右上の **「バッチを停止」** で止められます。処理中のファイル（生成中はチャンク）が終わった時点で止まり、状態は「停止（手動）」になります。ここまでの結果は残り、残りは次回のバッチで続きから処理します。
   - バッチが失敗・停止・時間切れになった場合は、「バッチ実行状況」の **「続きから再実行」** で残り（取り込み待ちの文書・QA 未生成のチャンク・質問の埋め込み待ち）だけを処理します。取り込み済みの文書や QA を生成済みのチャンクはやり直しません。QA 生成に 3 回失敗したチャンクは、毎晩同じところで時間を使わないよう対象から外れ、一覧に表示されます（「生成の対象に戻す」で再挑戦）。
   - 2回目以降のバッチは **変更のあった部分だけ** を処理します。Drive の更新日時・チェックサムが同じファイルは取り込みを省略し、内容が変わった文書も、変わっていないチャンクは埋め込みと生成済み QA をそのまま再利用します（ファイル別ログに「新規 / 再利用 / 削除」のチャンク数が出ます）。そのため、初回の QA 生成が済めば、夜間バッチは通常短時間で終わります。
   - 実行後は管理画面トップの **「直近の夜間バッチ実行状況」** で結果を確認します。状態の `completed` は「最後まで実行した」という意味で、全文書の取り込み成功を意味しません。**「取り込み（成功文書 / チャンク）」** と **「ファイル別ログ」** で、各ファイルが取り込めたか、失敗した場合はその理由（Drive の閲覧権限、本文抽出、埋め込みなど）を確認してください。

### ステップ 4: 一般ユーザーの利用

- 社員はブラウザから `https://<Google Cloud Console に登録したホスト名>:4443/` にアクセスし、各自の Google Workspace アカウントでログインして質問チャットを利用します。
- `許可 Google Workspace ドメイン` 以外のアカウントによるアクセスは自動的に遮断されます。
- 初回ログイン時に自動で一般ユーザーとして登録されます。事前の招待や登録作業は不要です。
- 一般ユーザーには管理画面への導線が表示されず、URL を直接開いてもチャット画面に戻されます。
- 特定のユーザーを管理者へ昇格できるようにするには、管理画面の **「ユーザー管理」** タブで「昇格を許可」します。

## LLM プロバイダ設定リファレンス

| プロバイダ | 生成 | 埋め込み | 既定エンドポイント | 必要な資格情報 |
|---|---|---|---|---|
| `ollama` | ○ | ○ | `http://localhost:11434` | 不要 |
| `lmstudio` | ○ | ○ | `http://localhost:1234/v1` | 不要 |
| `gemini` | ○ | ○ | `https://generativelanguage.googleapis.com/v1beta` | API キー |
| `anthropic` | ○ | **×** | `https://api.anthropic.com` | API キー |
| `openai` | ○ | ○ | `https://api.openai.com/v1` | API キー |

Claude API は埋め込みエンドポイントを提供しないため、埋め込みプロバイダには選択できません。

### 推奨モデルと埋め込み次元

| プロバイダ | 生成モデル例 | 埋め込みモデル例 | 次元 |
|---|---|---|---|
| `ollama` | `qwen3:4b` | `bge-m3` | 1024 |
| `lmstudio` | ロード中のモデル名 | `text-embedding-nomic-embed-text-v1.5` | 768 |
| `gemini` | `gemini-2.5-flash` | `gemini-embedding-001` | 768 / 1536 / 3072 |
| `anthropic` | `claude-sonnet-5` | — | — |
| `openai` | `gpt-5` | `text-embedding-3-small` | 1536 |

> **おすすめの構成**: 埋め込みは `ollama` + `bge-m3`（ローカル・無料・再インデックス不要）のまま据え置き、**生成だけ**を外部 API に切り替える構成です。埋め込みモデルを変えると全チャンクの再ベクトル化が必要になり、文書量によっては数時間〜複数夜かかります。
