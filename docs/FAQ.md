## 文書の更新・入れ替え

### Q. Drive の文書を更新しました。いつチャットの回答に反映されますか？

次の夜間バッチのあとです。夜間バッチは Drive の対象フォルダを毎晩読み直し、変わった文書だけを取り込み直します。

すぐに反映させたいときは、窓口の管理画面の「概要・バッチ状況」から「取り込みのみ実行」を押してください。文書の取り込みと検索用データの作成までを行います。

- 「フル実行（QA 生成あり）」は、想定 QA の生成まで行います。生成に使う AI を長い時間占有し、その間のチャットの検索がキーワード中心になるので、日中は「取り込みのみ実行」をおすすめします。
- 更新された文書の QA は、次の夜間バッチで作り直されます。

### Q. ファイル名を変えたらどうなりますか？ 別の文書として登録し直されますか？

登録し直されません。AskDrive は文書をファイル名ではなく Google Drive のファイル ID で見分けているので、名前を変えても同じ文書として扱います。次の夜間バッチで、一覧やチャットの出典の表示が新しい名前になります。

本文を読み直すかどうかは、Drive の「最終更新日時」が変わったかで決まります。

- **変わっていた場合**: 本文を読み直し、新しい名前で検索用データを作り直します。
- **変わっていなかった場合**: 名前だけを更新し、本文は読み直しません。検索用データの中には旧い名前が残るので、新しい名前そのもので検索したときのヒットが少し弱くなります（本文の内容での検索には影響しません）。

翌朝、「概要・バッチ状況」のファイルごとのログで、その文書が「更新」（読み直した）か「変更なし」（名前だけ更新）かを確認できます。

### Q. 対象フォルダからファイルがなくなったら、どうなりますか？

次の夜間バッチで、その文書をインデックスから完全に削除します。文書の本文、検索用データ、その文書から作った想定 QA・要約・回答のキャッシュがすべて消え、翌日からはチャットの回答に出てきません。ファイルごとのログには「Drive のフォルダから無くなったため、インデックスから削除しました」と残ります。

| 操作 | 結果 |
|---|---|
| 対象フォルダの外へ移動 | 削除 |
| ゴミ箱に入れる | 削除 |
| 対象フォルダの中のサブフォルダへ移動 | 削除されない（サブフォルダの中も対象です） |
| 共有を外すなどで AskDrive から見えなくなった | 削除 |
| 「ドキュメント」タブで対象外にしたフォルダの中へ移動 | 削除（対象外にした時点で削除） |

フォルダの一覧がエラーで取得できなかった夜（対象フォルダ自体の共有が外れた、Drive が一時的に応答しないなど）は、何も削除しません。一時的なエラーで全部の文書が消えることはありません。

ファイルを対象フォルダに戻せば、次の夜間バッチで取り込み直します。ただし想定 QA や要約も消えているので、すべて作り直しになります。

### Q. 旧版のマニュアルを新版に差し替えたいです。旧版の内容が回答に混ざらないようにできますか？

できます。新版を対象フォルダに入れたうえで、旧版を次のどちらかで外してください。チャットの AI 要約は検索で見つかった抜粋だけを根拠に書くので、外した旧版の内容が回答に混ざることはありません。

- **旧版を対象外にする（すぐ反映）**: 窓口の管理画面の「ドキュメント」タブで、旧版の行の「対象外にする」を押します。旧版の情報（想定 QA と回答のキャッシュを含む）はその場で削除されます。「旧版」フォルダにまとめているなら、そのフォルダごと対象外にできます。Drive のフォルダ構成を変えられない場合はこちらです。
- **旧版を対象フォルダの外へ移す（ゴミ箱でも可）**: 次の夜間バッチで旧版の情報が削除されます。

- 「旧版」などのサブフォルダに移しただけでは、対象フォルダの中にある限り取り込まれ、旧版の内容も回答に使われます。そのフォルダを対象外にしてください。
- 夜間バッチまでは旧版で回答します。すぐに切り替えたいときは「取り込みのみ実行」を押してください。
- 新版の想定 QA は、夜間の時間が足りないと翌晩以降に作られます。それまでも新版の抜粋と AI 要約で回答するので、内容は新版に基づきます（回答に少し時間がかかります）。
- 利用者のチャット履歴には、旧版で答えた当時の回答がそのまま残ります。

### Q. 同期フォルダの中に、回答に使いたくないファイルがあります。外せますか？

外せます。窓口の管理画面の「ドキュメント」タブで指定します。

- **ファイル**: 文書一覧の行の「対象外にする」→「このファイルだけ」。
- **フォルダ**: 同じメニューから、その文書が入っているフォルダを選びます（フォルダの下もすべて対象外になります）。フォルダが選べないとき（まだ同期していない文書など）は、カードの欄にフォルダの Drive の URL を貼り付けてください。

指定した時点でインデックスから外れ、チャットの回答に使われなくなります（夜間バッチを待つ必要はありません）。以降の夜間バッチでもダウンロードしません。Drive の ID で覚えているので、ファイル名を変えても対象には戻りません。

- 対象外の一覧には、指定した人と日時が出ます。「対象に戻す」を押すと、次の夜間バッチで取り込み直します（想定 QA や要約は作り直しになります）。
- バッチの実行中は変更できません。終わってから（または「停止」してから）操作してください。
- 同期フォルダそのものは対象外にできません。同期するフォルダを変える場合は「設定」から変更します。

### Q. Drive の同期が止まりました。認証した担当者が異動・退職しました。

Google アカウント認証では、認証した人の Google アカウントの権限で Drive を読みます。その人のアカウントが止まったり、対象フォルダの共有から外れたりすると、夜間バッチの同期が止まります。窓口の管理画面の「設定」→「Google Drive 同期設定」で、次のどちらかを行ってください。

- **ほかの人が認証し直す**: 「切断」を押してから、対象フォルダを見られる別のアカウントで接続し直します。
- **サービスアカウントに切り替える**: カードの下の「詳細設定：サービスアカウントを使う」を開き、サービスアカウントの JSON キーを貼り付けて、対象フォルダをサービスアカウントのメールアドレスに共有します。個人のアカウントに左右されないので、担当者が変わっても同期が続きます（Google Cloud でのサービスアカウントの作成が必要です）。

認証が 7 日ほどで切れる場合は、Google Cloud の OAuth 同意画面が「外部」の「テスト中」になっている可能性があります。全体管理者に、社内向け（「内部」）にするよう依頼してください。

### Q. どんなファイルが取り込まれますか？

文書のファイルだけです。

| 種類 | ファイル |
|---|---|
| Google | ドキュメント、スプレッドシート、スライド |
| Office | Word（.docx / .doc）、Excel（.xlsx / .xls）、PowerPoint（.pptx / .ppt） |
| その他 | PDF、テキスト（.txt）、Markdown（.md）、CSV、HTML |

これ以外（バッチファイル、.exe などのプログラム、.py などのソースコード、画像、設定ファイルなど）は、ダウンロードせずに対象外にします。「ドキュメント一覧」では状態が「skipped」になり、理由が表示されます。

文書の種類でも、窓口管理者が対象外にしたファイル・フォルダは取り込みません（「同期フォルダの中に、回答に使いたくないファイルがあります。外せますか？」を参照）。

- 旧形式の .doc / .xls / .ppt を読むには、サーバーに LibreOffice が必要です（全体管理の「インストールとアップデート」で確認できます）。
- スキャンした PDF（文字のない画像だけのページ）は、文字を読み取れないので検索できません。

## 回答の仕組み

### Q. チャットはどうやって回答していますか？

質問を次の順に調べ、最初に見つかった方法で答えます。

| 段階 | 回答のしかた | 速さ |
|---|---|---|
| Tier 0 | 以前とまったく同じ質問への回答（キャッシュ） | 即答 |
| Tier 1 | 夜間バッチで文書から作っておいた想定 QA | 即答 |
| Tier 2 | 文書の該当箇所（抜粋）を検索し、AI がそれを要約 | 数秒〜数十秒 |
| Tier 3 | 該当する文書が見つからない（未回答として記録） | — |

Tier 2 の AI 要約は、検索で見つかった抜粋だけを根拠にします。抜粋に書かれていないことは「確認できませんでした」と答え、推測では答えません。ただし「この名前は命名規則に沿っていますか？」のように、文書の規則に当てはまるかを尋ねる質問には、その規則を当てはめて答えます（名前そのものが文書に無くても答えます）。AI に渡す抜粋は、クラウド API の AI なら最大 8 件、ローカル LLM なら最大 4 件で、最も関係の深い文書は見つかった部分の前後も渡します。規則が文書のあちこちに書かれていても、まとめて当てはめられるようにするためです。

クラウド API の AI を使う窓口では、規則に沿っているかの確認（「この名前は命名規則に沿っていますか？」）や、文面の奥に目的がある質問（「Adobe Acrobat を使いたい」→ PDF を編集したい）には、関係する文書を丸ごと読ませ、考えさせてから答えます。規則の目的に照らした判定と直し方の例や、社内の手続きに加えて目的に合う別の方法（許可されているアプリなど）も案内します。そのぶん回答に数秒〜10 秒ほど余計にかかります。「USBメモリを使っていいですか」のように資料にそのまま答えがある質問は、これまでどおり短く答えます。ローカル LLM の窓口では行いません。

### Q. 回答できなかった質問はどうなりますか？

Tier 2（抜粋のみ）や Tier 3（未回答）になった質問は、管理画面の「未回答・解消質問」に載ります。夜間バッチは、これらの質問に関係する文書の想定 QA を優先して作り、作れた質問は「解消」として一覧の下段に移します。次からは即答できるようになります。

Tier 2 は似た箇所を必ず探し出すので、Tier 3 になるのは、ほとんどの場合、取り込まれた文書が 1 つもないとき（Drive の同期が失敗しているなど）です。Tier 3 が続く場合は、「概要・バッチ状況」で夜間バッチの結果を確認してください。抜粋が的外れな質問が多い場合は、その内容を書いた文書を対象フォルダに追加してください。

### Q. チャットの「解決した」ボタンと「この回答に追加で質問」は、何に使われますか？

利用者が回答に満足したかを知るためのものです。

- **「解決した」**: 押された質問は、解決したものとして数えます。管理画面の未回答の一覧からは外れますが、夜間バッチの想定 QA の生成の対象には残ります（次からは即答できるように）。もう一度押すと取り消せます。
- **「この回答に追加で質問」**: 追加で質問されたら、前の回答では解決しなかったとみなします。想定 QA で即答した質問でも未回答の一覧に載り、「回答の内容が古いか、的外れの可能性があります」と表示されます。その QA の元の文書を見直してください。

どちらも押すかどうかは利用者の任意です。押されなかった質問は、回答のしかた（Tier）から解決したかを推定します。

## 画面の見方

### Q. 「API利用量・ログ」の数字は何を表していますか？

直近 30 日の値です。

| 表示 | 意味 |
|---|---|
| 質問数 | チャットで質問された回数（追加の質問も 1 回と数えます） |
| 解決・未解決 | 解決＝想定 QA で答えて追加の質問がなかった、後日 QA を作った、または利用者が「解決した」を押した質問。それ以外が未解決 |
| 質問の処理に使ったトークン | チャットの検索と AI 要約で使ったトークン数 |
| 夜間バッチで処理したトークン | 文書の取り込みと想定 QA の準備で使ったトークン数 |
| 返答速度 | AI 要約にかかる平均時間から「良好」（15 秒以内）・「ふつう」（40 秒以内）・「やや遅い」で表示。添え書きは、夜間バッチで準備した QA から即答できた質問の割合 |

大きな数は「12.3 万」のように短く表示します。マウスを重ねると正確な数が出ます。

### Q. 「利用状況」タブでは何が分かりますか？

直近 7 日・30 日・90 日（上の切り替え）の、この窓口の使われ方です。

- **よく使うユーザー**: ユーザーごとの質問回数・回答に使ったトークン・解決率・最後の質問日時です。「質問回数」と「トークン」で並び順を切り替えられます。ログインなしの利用は「ゲスト（ログインなし）」にまとめて表示します。
- **よくある質問**: 2 回以上聞かれた質問を、回数の多い順に表示します。空白・句読点・全角と半角の違いは同じ質問とみなします。追加の質問は数えません。「未解決が多い」と表示された質問は、答えになる文書がないか、分かりにくい可能性があります。手順書を追加したり書き直したりする候補にしてください。

トークンは、検索と AI 要約で使った分です（夜間バッチの分は含みません）。この機能を入れる前（アップデートする前）の質問は集計に含まれません。

### Q. 「利用状況」で、誰が何を質問したか分かりますか？

分かりません。ユーザーごとに表示するのは回数とトークンなどの数だけです。「よくある質問」には誰が聞いたかを表示せず、1 回だけの質問も表示しません。個人的な相談の内容が、ほかの人に知られないようにするためです。

### Q. 返答速度が「やや遅い」です。どうすればよいですか？

即答（Tier 0 / 1）の割合を増やすのが効果的です。

- 夜間バッチの QA 生成が毎晩最後まで終わっているか、「概要・バッチ状況」で確認してください。
- よく聞かれる内容は、見出しのはっきりした文書（Google ドキュメントや Markdown）にすると、想定 QA の質が上がります。
- AI 要約そのものの速さは、全体管理者が設定するサーバーやモデルによります。

### Q. 夜間バッチの QA 生成が朝までに終わりません。

夜間バッチをクラウド API で実行している場合は、「設定」の **「同時に生成する数」**（初期値 4）を増やすと早く終わります。API の利用上限（1 分あたりのリクエスト数など）を超えない範囲にしてください。上限に当たると、AskDrive が自動で同時に生成する数を減らすので、増やしすぎても失敗はしませんが、それ以上は速くなりません。

- 同じ API キーをほかの窓口と共有している場合、その窓口と合わせてこの数までになります。窓口ごとに数が違うときは、小さいほうが使われます。
- 窓口ごとに別の API キーにすると、ほかの窓口と上限を分け合わずに済みます。
- ローカル LLM（Ollama など）の場合は、1 件ずつしか生成できません。この設定は使われません。
- 処理しきれなかった分は、次の夜に続きから生成します。

### Q. トークン効率が「要改善 (C)」の文書があります。

「ドキュメント」タブで、トークン効率「要改善 (C)」で絞り込むか、「効率の悪い順」に並べると一覧できます。

PDF の「要改善 (C)」は、ページにほとんど文字がない（スキャンした紙や、画像だけのページ）という意味です。画像の中の文字は検索できないので、元の文書（Word や Google ドキュメント）があればそちらを対象フォルダに入れてください。スクリーンショットの多い手順書でも、説明の文章がしっかりあれば「要改善」にはなりません。画像の中のボタン名や設定値など大事な情報は、本文にも書いておくと検索で見つかります。

### Q. API 通信エラーの一覧の「確認済みにする」を押すと、どうなりますか？

一覧から消えるだけで、記録は残ります。把握済みのエラーを片付けておくと、新しいエラーに気づきやすくなります。一覧には直近 7 日間のエラーだけを表示し、API の利用ログは 90 日で自動的に削除します。

## プライバシー

### Q. 利用者の質問は、どこに保存され、誰が見られますか？

すべて、AskDrive のサーバーの中の、その窓口のデータベースに保存されます。

| 保存されるもの | 見られる人 |
|---|---|
| チャットの履歴（質問・回答） | 質問した本人だけ（チャット画面の「履歴」から。本人が削除できます） |
| 回答できなかった質問の文面（「未回答・解消質問」） | その窓口の管理者（誰が質問したかは記録しません） |
| API の利用ログ（回数・トークン数・エラー） | その窓口の管理者（質問の文面や文書の内容は記録しません） |
| 利用状況（ユーザーごとの質問回数・トークン、よくある質問） | その窓口の管理者。全窓口の合計は全体管理者（ユーザーごとの記録に質問の文面はありません。90 日で削除します） |

ログインなし（ゲスト）で使う窓口では、チャットの履歴を保存しません。

外部の AI サービス（クラウドの API）を使う設定の場合は、質問と、検索で見つかった文書の抜粋がそのサービスに送られます。ローカルの AI（Ollama）だけを使う設定なら、外部には送りません。
